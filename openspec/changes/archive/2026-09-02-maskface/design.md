## Context

本项目从零开始构建，无现有代码。唯一约束来自 Plan.md 中定义的技术栈选择和项目结构。使用 uv 管理依赖，目标平台为 Windows 桌面。

## Goals / Non-Goals

**Goals:**
- 提供模块化的代码结构，人脸处理、音频处理、GUI 各自独立
- 首次运行自动下载模型，后续无需联网
- 双击 .bat 即可启动，零配置

**Non-Goals:**
- 不支持实时视频流处理
- 不支持 GPU 加速（仅 CPU）
- 不提供 CLI 以外的批量处理能力（CLI 作为备选保留）
- 不处理 1080p 以上分辨率（内存考虑）

## Decisions

### 1. uv 作为包管理器
- **选择**: 使用 uv 替代 pip + venv 手动管理
- **理由**: 比 pip 更快，内置 venv 管理，生成 pyproject.toml 而非 requirements.txt，符合现代 Python 项目实践
- **备选方案**: pip + venv + requirements.txt，更传统但需手动管理虚拟环境

### 2. OpenCV DNN SSD 模型
- **选择**: res10_300x300_ssd_iter_140000_fp16.caffemodel
- **理由**: 轻量（约10MB），CPU 推理速度快，精度足够用于人脸模糊场景
- **备选方案**: MTCNN（精度更高但慢）、YOLO-face（需额外依赖）

### 3. 跳帧 + 线性插值
- **选择**: 每 5 帧检测一次，中间帧线性插值人脸位置
- **理由**: 大幅降低计算量（约 5x），1080p 视频人脸的帧间移动通常很小，视觉上不可察觉
- **备选方案**: 逐帧检测（更精确但 5x 慢）

### 4. 模块拆分
- **选择**: face_detector.py + voice_changer.py + app.py 三个文件
- **理由**: 职责清晰，可独立测试，CLI 备选方案可直接复用
- **备选方案**: 单文件（简单但不可维护）

### 5. moviepy 处理音视频
- **选择**: moviepy 2.x 作为音视频分离/合成工具
- **理由**: 自带 ffmpeg，无需额外安装，API 简洁
- **备选方案**: 直接调用 ffmpeg 命令行（灵活但需用户安装 ffmpeg）

### 6. Gradio 作为 GUI
- **选择**: Gradio 4.x，inbrowser=True 自动启动浏览器
- **理由**: 纯 Python，零前端代码，拖拽上传/进度条/下载等组件内置
- **备选方案**: PyQt/Tkinter（需安装运行时，UI 开发成本高）、Flask + 前端（开发量大）

## Risks / Trade-offs

- [大视频内存占用] 建议处理 1080p 及以下；可考虑分段处理作为未来优化
- [首次模型下载需联网] 启动时明确提示用户；下载失败给出清晰错误信息
- [SSD 模型对小脸/侧脸检测率低] 调节置信度阈值可部分缓解；极端情况可接受
- [pitch shift 大幅改变可能导致音频失真] 默认 -5 半音在合理范围内；极端值由用户自行承担
